# Domain Companion: Data & Storage

Apply this companion when auditing code interacting with relational databases (PostgreSQL, MySQL), NoSQL stores (MongoDB, DynamoDB), ORMs (Prisma, TypeORM, Hibernate, SQLAlchemy), and caches (Redis).

## Core Disciplines

1. **Transaction Integrity & Boundaries**:
   - Multi-table mutations representing a single business transaction must execute inside an explicit database transaction.
   - External network calls (sending emails, calling external payment gateways) must NEVER be executed inside an open database transaction, as latency causes row lock contention and connection pool starvation.
2. **Query Performance & Index Awareness**:
   - Queries filtering on high-cardinality columns must align with existing database indexes.
   - Look for unintentional full-table scans generated by ORM methods (e.g. `findAll()`, `.filter()` without limit).
3. **Connection Lifecycle & Leaks**:
   - Acquire and release connections via pools with explicit timeouts.
   - Long-lived transactions or unclosed cursors must be avoided.
4. **Consistency & Concurrency**:
   - Check isolation levels (Read Committed vs Repeatable Read vs Serializable).
   - Use optimistic locking (`version` column) or `SELECT ... FOR UPDATE` when reading state that will be modified conditionally.
5. **Caching Invalidation & Drift**:
   - Cache writes must invalidate or update entries synchronously or via transactional outbox patterns to prevent stale reads and split-brain states.
